# Commands: archive, restore, list-archived, inspect, purge-tmp

## Archive a thread (`/threads archive [thread-name]`)

- If thread name not provided: list threads with numbers, ask which to archive, wait for reply.
- **Before calling `archive_thread`**, draft a search-optimised summary:
  1. Read the thread's README.md and decisions. For sessions, read frontmatter only (date, summary, keywords) — read full session files only if you need more detail.
  2. Aggregate keywords from all session frontmatter, then enrich with terms from decisions and README.
  3. Compose:
     - **`summary`** (one sentence): what this thread was about, in the user's domain language
     - **`keywords`** (list): aggregated from session frontmatter + decisions + README, plus synonyms. 5–20 is typical.
     - **`body`** (markdown narrative): topic-rich prose for embeddings — what was discussed, decisions made and why, systems/files touched, vocabulary and synonyms. Be concrete.
- Call `mcp__plugin_ai-workspace_threads__archive_thread(workspace_dir, thread_name, summary, keywords, body)`
- The tool creates `archive/{YYYY}-{name}.tar.gz`, writes `archive/{YYYY}-{name}.md`, then deletes `threads/{name}/`
- If the thread contains symlinks, the tool refuses — resolve or remove them first
- Report the resulting archive paths to the user

## Restore an archived thread (`/threads restore [archive-base]`)

- `archive-base` is the filename stem, e.g. `2026-last-months-project`
- If not provided: call `list_archived_threads` and ask the user to choose by number
- Call `mcp__plugin_ai-workspace_threads__restore_thread(workspace_dir, archive_base)`
- The tool extracts back into `threads/{name}/`, writes a `sessions/{YYYYMMDD}-restored.md`, deletes the archive files. Reports final path (appends `-restored`, `-restored-2`, etc. on collision)

## List archived threads (`/threads list-archived`)

- Call `mcp__plugin_ai-workspace_threads__list_archived_threads(workspace_dir)` and output the result directly
- Each line shows: archive base, dates, inline keywords

## Inspect an archive (`/threads inspect [archive-base]`)

Also recognized: "search archives for X", "any archived threads about X"

1. Call `list_archived_threads` to see all bases + keywords
2. Read `archive/{base}.md` for likely candidates (summary + body)
3. For deeper investigation: call `mcp__plugin_ai-workspace_threads__inspect_archive(workspace_dir, archive_base)`
4. Read files under `archive/tmp/{base}/{thread-name}/` — sessions, decisions, etc.
5. When done, suggest `/threads purge-tmp`

Inspect is non-destructive. Use `/threads restore` when the user actually wants the thread back.

## Purge archive tmp (`/threads purge-tmp`)

- Call `mcp__plugin_ai-workspace_threads__purge_archive_tmp(workspace_dir)`
- Wipes `archive/tmp/` entirely. Safe — files can be regenerated by re-running `inspect_archive`.
